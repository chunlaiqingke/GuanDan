# Phase 02：掼蛋核心逻辑（纯 C++ 规则引擎）

完成牌编码、发牌、牌型识别、大小比较（含逢人配 / 级牌提升 / 同花顺 / 天王炸），全部为纯函数，不依赖网络 / IO。不含回合状态机、倒计时、进贡 / 接风 / 升级（这些归 Phase 03 对战流程）。

## 文件清单

### 规则引擎（guandan-server/src/guandan/，namespace `guandan::rules`）
- `Card.h/.cpp` — 牌整数编码（`rank*4+suit`，2..10=2..10、J/Q/K/A=11..14、小王=16、大王=17）；花色枚举；王 / 逢人配判定；`buildDeck()`（两副 108 张）、`shuffle(deck, seed)`（std::mt19937 可复现）、`deal(deck)`（轮转发 4×27）
- `Pattern.h/.cpp` — 牌型枚举 + `classify(cards, levelRank)` 识别一手牌（含逢人配）
- `Compare.h/.cpp` — `compare(a, b, levelRank)` 大小比较 + `effectiveRank()` 级牌提升

## 已实现规则（按 spec + 用户确认口径）

1. **固定长度**（用户确认）：顺子 = 5 张、连对 = 3 对（6 张）、飞机 = 2 组三张（6 张）。
2. **级牌提升**：`大王 > 小王 > 级牌 > A > K > … > 2`（`effectiveRank` 映射为 100/99/98/14…2）。
3. **顺子类按自然点比较**：顺子 / 连对 / 飞机 / 同花顺的顶张按自然牌点比，不提升级牌（避免"打 J 时 J 顶顺子误压 Q 顶顺子"）。
4. **2 / 王不进顺子 / 连对 / 飞机**；A 只能作顺子高张（A K Q J 10）。
5. **炸弹**：4~8 张同点（两副牌每点最多 8 张）；张数多者大，同张数比点（级牌炸弹提升）。
6. **同花顺**：固定 5 张同花连续，按 spec 简化为"5 张炸弹"（比张数再比自然顶张）；6 张及以上炸弹可压同花顺。
7. **天王炸**：2 小王 + 2 大王，最大；其余王组合（一大一小、3 王等）判非法。
8. **逢人配（红桃级牌）**：可配 2..A 任意点（枚举赋值，≤2 张）；纯逢人配（单张 / 对子）按级牌本身点识别；多解释时取最强。

## 已知限制 / 假设

1. **同花顺 vs 同张数普通炸弹**：按 spec"先按同花顺=同张数炸弹"实现（即同花顺=5 张炸弹，比自然顶张），未做"同花顺严格大于同张数普通炸弹"的细分，后续可精化。
2. **进贡 / 接风 / 升级**：依赖回合级状态（头游 / 末游 / 当前级），归 Phase 03 对战流程实现。
3. **三带二对子不能是王**：王每种最多 2 张，无法组成对子外的合法结构，故王不参与三带二 / 炸弹（除天王炸）。
4. **发牌随机源**：用 `std::mt19937 + seed`（可复现测试），生产期可换成 `std::random_device` 播种。
5. **逢人配枚举复杂度**：单手最多 2 张逢人配，枚举 13^2 种赋值，开销可忽略。
